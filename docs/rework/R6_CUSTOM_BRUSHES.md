# R6 — Developer tools and custom Ant brushes

Completed September 12, 2026. Verification results and source entry points are below.
This is package 4; collision expansion, full Ant environment acceptance, performance
budgets and final blank-project learning acceptance remain separate R6 packages.

## Create and use a project brush

1. In the object creation menu choose **Create Project Source**, select **Brush**,
   enter a C++ class name and choose **Generate**. The editor writes
   `Source/Editor/<Name>.h`, adds the module to `Config/Modules.pfconfig`, and regenerates
   `Source/Runtime/GeneratedRegistration.h`. Brush generation starts the existing
   asynchronous build/reload workflow. Compiler failures appear in build output and
   preserve the previously loaded runtime.
2. The generated class derives from `pipeframe::SchemaBrush<YourBrush>`. Its own
   `Schema()` contains typed settings and validation. Implement `PaintData(cell, old)`
   for numeric data or `Paint(cell, oldTile)` for visual tiles. No native types, picking,
   custom undo stack or project-specific editor panel are needed.
3. In **Assets → Maps**, open a map for editing and choose the project brush above
   the standard settings. Its controls are generated by the public declarative
   `SchemaInspector`. The brush creates its named numeric layer when first selected;
   creating that layer is a separate undoable document operation.
4. Choose Pencil, Line, Rectangle, Outline, Fill or Circle and paint. The shared
   Erase toggle also clears numeric data. Pencil radius
   and axis lock remain available. The same effect works across gesture shapes.
   Escape cancels a pending stroke. Undo/redo and Save Map use the existing document
   history and save workflow. Select **Visual Tiles** to return to tile painting.
5. Save/reopen preserves the data. Brush settings are session settings and return to
   schema defaults on plugin reload; authored data is preserved. Rebuild/reload after
   editing brush source uses the normal toolbar action.

Minimal brush shape (see the generated header for the complete schema):

```cpp
class MoistureBrush final : public pipeframe::SchemaBrush<MoistureBrush> {
public:
    double amount{0.5};
    static auto Schema() {
        return pipeframe::ComponentSchema<MoistureBrush>("garden.moisture", "Moisture")
            .Editable({.key="amount", .displayName="Amount",
                       .kind=pipeframe::PropertyKind::Number, .defaultValue=0.5,
                       .minimum=0, .maximum=1}, &MoistureBrush::amount);
    }
    std::string_view DataTarget() const override { return "garden.moisture"; }
    double PaintData(pipeframe::GridCoordinate, double) const override { return amount; }
};
```

For a hand-authored project, call `RegisterBrush<MoistureBrush>("Garden")` in its runtime
composition root. Generated projects add this call automatically. The runtime host
publishes these factories through `PluginRegistrar` and the existing
`ExtensionPoint::EnvironmentBrush` registry. Factories carry stable IDs, labels and
categories; compatibility is defined by a tilemap target and the brush's numeric
layer ID/range. Authoring brushes are stopped/paused editor tools; they do not edit
assets during simulation playback.

## Engine ownership and lifecycle

`TilemapPaintTool : EditorTool` owns input capture and cell-space gestures.
`EnvironmentBrush`/`BrushTool` supply effects, settings and observational hooks:
`OnActivate`, `OnBegin`, `OnUpdate`, `OnPreview`, `OnEnd`, `OnCancel`, `OnDeactivate`,
and `OnTeardown`. Hooks are `const noexcept`; they must not mutate the document.
`OnTeardown` releases attachment resources when a tool detaches/reconfigures to a
new effect or is destroyed; an effect may subsequently be activated again.

The project supplies effects, never a second event dispatcher or undo stack.
`TilemapEdit` owns bounds, sampling, deduplication, revision checks and transaction
validation. `TilemapPatch` stores before/after values; it validates every cell before
writing any cell. Settings changes cancel pending gestures. Pencil applies an effect
once per cell per stroke, regardless of mouse event frequency. Rectangle previews
replace their previous endpoint result rather than accumulating changes.

The existing host inverse camera/transform mapping and Playground clipping also
apply to project brushes. Hidden/locked visual layers retain their tile rules;
numeric layers have independent locks and do not depend on visual layer visibility.
Numeric layer undo validates its own lock, current values and bounds.

The host releases plugin-owned brush instances and factory closures **before** library
unload, including direct reload/unload calls. Failed reload retains the old runtime;
successful reload cancels the old gesture and discovers the replacement catalog.
Deleted/changed targets disable captured tools. Switching projects rejects unsaved
work or active capture; after save/cancel, project activation releases old tools.
This package introduced plugin ABI **9**. Package 5 advances it to **10**; rebuild project libraries with the current SDK.

## Independent data layers and Ant

Tilemap format **v3** adds named numeric data layers, finite ranges, locks and cell
values. v1/v2 maps remain readable. Numeric data does not create visual tile IDs or
collision. Layer and map budgets bound allocations. Save/reopen, make-unique,
resize/crop/resample and snapshot undo retain numeric layers. The selected data layer
has a green editor overlay; committed occupied cells are cached by map revision,
with pending changes overlaid without scanning the whole grid every idle frame.

`AntFoodBrush` lives in `examples/AntSimulation/Source/Editor/AntFoodBrush.h`.
Its schema exposes **Food per cell** (integer 1–10000) and **Erase food**. It paints
`ant.food-density` using any of the shared gesture shapes. First creation preserves
legacy `Food` tiles using the original default seven units per cell; solid cells are
excluded. This one-time migration is undoable. Existing maps without the density
layer continue to use the legacy Food-layer configuration.

When a saved Ant map has a density layer, `WorldMapLoader` reads its exact quantities;
zero means no food, walls take priority, and nonintegral/out-of-range quantities are
rejected before replacing the environment. Save and reset/reload the simulation to
apply authored changes. The original live simulation brush remains a separate
transient interaction; it does not write these authored assets.

  compilation, external engine consumer compilation and Ant dependency isolation.
- `CustomBrushAcceptance` verifies schema bounds, independent numeric data, freehand/
  rectangle/circle, shared eraser, deduplication, bounds, preview/cancel, lifecycle,
  atomic stale/locked patch rejection, resize undo and save/reopen.
- `ProjectBuildAcceptance` generates and compiles a new brush in an independent project,
  discovers its factory, edits settings, reloads during capture, rejects switching while
  a clean document has active capture, and verifies post-cancel project activation.

  declarative views, then deletes a transformed target during custom capture.
- `AntWorldMapLoaderRegression` verifies validated Ant food settings and exact authored
  quantities reaching simulation cells while preserving existing PNG/tilemap parity.
